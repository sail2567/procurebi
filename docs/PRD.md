# LLM 采购成本智能分析平台 — 产品设计文档

> 代号：ProcureBI  
> 版本：v0.1（草稿）  
> 日期：2026-10-19  
> 定位：简历项目 / 个人作品

---

## 1. 项目背景

企业同时采购多家大模型服务（OpenAI、Anthropic、DeepSeek、通义等），账单、调用量、单价、配额分散在各类 Excel 和 PDF 合同中：

- 成本口径不统一，难以横向对比
- 想知道「钱花在哪个供应商、哪个应用上」需要人工翻表
- 比价、续约、配额管理依赖手工整理

本项目建设一个面向企业采购场景的 BI 数据智能体平台：上传采购单据即可查询，用自然语言提问，自动生成 SQL、图表和报表。

## 2. 产品定位

**一句话**：一个能读懂任意采购单据、用自然语言做成本分析的 BI 智能体。

- **目标用户**：采购、财务、业务线负责人（演示场景）
- **核心差异化**：不锁定固定表结构，上传新 Excel 自动建表，无需改代码即可查询
- **不是**：不是通用 BI 工具，不是模型网关，不是账单自动对接平台

## 3. 核心使用场景

| 场景 | 用户动作 | 系统能力 |
|---|---|---|
| 成本总览 | 上传各厂商账单 Excel | 自动建表，问「本月各供应商花了多少」并出图 |
| 比价 | 上传多家报价单 | 「同等能力模型哪家单价最低」 |
| 配额跟踪 | 上传用量与配额表 | 「哪些合同承诺量快用完了」 |
| 合同查询 | 上传合同 / 招标 PDF | 抽取关键字段，回答条款与承诺量问题 |
| 月度报告 | 自然语言发起 | 自动汇总数据并生成可视化报表 |

## 4. 功能范围

### P0 —— MVP（必须完成）

**账号与权限**
- 管理员 / 普通用户两种角色，账号由管理员创建，不开放注册
- 登录、退出、修改密码；禁用或重置密码后旧会话立即失效
- 普通用户可问数、看报表、看数据集；上传与删除仅管理员
- 后台管理：概览、用户管理、合同文档管理、操作日志

**数据接入**
- Excel 上传、解析预览
- 字段类型推断、表头清洗
- 自动动态建表
- 数据集登记与列表展示
- 上传质量报告：源行 / 可导入 / 空行 / 重复行 / 异常单元格与问题清单
- 相同文件按 SHA-256 去重，可选择强制导入副本

**数据集管理**
- 字段预览
- 重新上传与版本标识
- 删除数据集

**智能问数**
- 自然语言 → SQL → 结果表格
- 多轮追问（保留上下文）
- SQL 可展开查看，保证可追溯
- 查询失败自动重试纠错

**可视化**
- 根据查询结果自动选择图表类型
- 结果保存为卡片，拼装看板
- 看板导出

**BI 报表**
- 按字段语义自动识别账单、配额、模型清单与价目表
- 数据集切换、期间筛选（含上月 / 上季度）与环比
- 供应商下钻到模型 / 应用 / 月度结构
- 年度预算执行对比与采购底表汇总
- 多币种（USD → CNY）折算与口径说明
- 保存报表视图（数据集 + 期间 + 供应商）
- Excel / PDF 导出，只读分享链接（限流、可撤销）

### P1 —— 已实现的增强

- PDF 合同 / 招标文件解析与条款问答（RAG），回答附文档与页码引用
- 合同条款点击查看原文
- 跨供应商比价（模型清单 / 价目表 / 报价单）
- 成本异常归因与风险洞察
- 尚未实现：模型替换模拟、定时生成月度报告

### 明确不做（Non-goals）

- 全量对接厂商真实账单 API
- 多租户、复杂 RBAC、审批流
- 拖拽式通用 BI 建模
- 通用 PDF 表格结构还原
- 移动端适配

## 5. 核心流程

```
上传 Excel
  → 解析工作簿 / 工作表
  → 类型推断 + 表头清洗
  → 动态建表（ds_ 前缀）
  → 登记数据集
        ↓
自然语言提问
  → 意图识别
  → Schema 反射（information_schema + 样例值，Redis 缓存）
  → 生成 SQL
  → SQL 校验（只读 / 白名单 / LIMIT / 超时）
  → 执行查询
  → 失败则纠错重试
  → 生成图表配置 + 自然语言解读
  → 保存为报表卡片
```

## 6. 页面结构

| 页面 | 主要内容 |
|---|---|
| 数据接入 | 拖拽上传、解析预览、字段确认 |
| 数据集 | 数据集列表、字段与样例数据 |
| 智能问数 | 对话区、SQL 折叠、结果表格、图表 |
| BI 报表 | 看板卡片、期间筛选、Excel / PDF 导出、只读分享链接 |
| 合同中心（P1） | 合同列表、关键字段、条款问答 |

## 7. 技术方案（概要）

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + Vite + Pinia + ECharts，自定义 CSS |
| 后端 | FastAPI + SQLAlchemy + Pydantic v2 |
| Agent | LangChain + LangGraph |
| 数据库 | PostgreSQL 16 + pgvector |
| 缓存 / 状态 | Redis 7 |
| 部署 | Docker Compose |
| 大模型 | OpenAI 兼容协议，可切换 DeepSeek / Qwen / OpenAI |

## 8. 关键设计决策

1. **动态 Schema**：每张 Excel 工作表对应一张物理表；尽量保留中文表头作为列名，仅处理重复、空值和特殊字符。
2. **轻量元数据**：不单独维护语义字典。建表时可选执行 `COMMENT ON COLUMN`，查询时读取数据库注释与样例值；仅保留一张最小的 `datasets` 登记表。
3. **SQL 安全沙箱**：只读数据库账号、sqlglot AST 校验（仅允许 SELECT）、强制 LIMIT、语句超时。
4. **图表配置化**：模型只输出结构化 chart spec（类型、维度、指标、聚合），由前端渲染，不让模型生成前端代码。
5. **Redis 的四个用途**：LangGraph 会话状态、查询缓存、异步任务进度、调用限流。
6. **不可信输入**：上传文件内容一律视为数据，防止 Prompt Injection 影响系统指令。

## 9. 非功能要求（演示规模）

- 单文件上传 ≤ 20MB，≤ 5 万行
- 问数响应：流式输出，首屏 ≤ 10 秒
- 查询结果默认返回 ≤ 500 行
- 关键操作有日志，便于演示排查

## 10. 里程碑

| 阶段 | 目标 | 产出 |
|---|---|---|
| 第 1 周 | 数据接入闭环 | Excel 上传、动态建表、数据集列表 |
| 第 2 周 | 基础问数 | SQL 沙箱、NL2SQL、结果表格 |
| 第 3 周 | Agent 与可视化 | LangGraph 状态机、多轮、图表、Redis |
| 第 4 周 | 报表与交付 | 看板、导出、PDF（选做）、部署、评测集 |

## 11. 风险与取舍

| 风险 | 应对 |
|---|---|
| 列名模糊导致 NL2SQL 准确率低 | 建表时生成列注释；prompt 附带样例值 |
| Excel 多级表头 / 合并单元格 | 约定模板 + 预处理规则，不做通用还原 |
| Schema 过多导致 prompt 超长 | 按表名和注释做相关性筛选，只保留 top-k |
| PDF 解析工作量失控 | 只做关键字段抽取 + 条款 RAG |
| LangChain / LangGraph 版本变动 | 锁定依赖版本，README 记录环境 |

## 12. 简历亮点映射

- 动态 Schema 接入：任意采购 Excel 上传后自动推断类型、建表登记，无需改代码即可查询
- LangGraph 数据分析 Agent：意图路由、Schema 召回、SQL 生成与自修复、图表生成
- SQL 安全沙箱与评测集：只读账号 + AST 校验 + 超时限制，基于 gold question 衡量准确率
- Redis 应用：会话持久化、查询缓存、异步任务进度推送
- Docker Compose 一键部署，提供在线 Demo
